Investment Decision Operating System (IDOS)
Software Design Document (SDD)
14: CI/CD Pipeline & Operational Workflows
Versión: 1.3
Estado: Aprobado

1. Objetivo
Describir el pipeline de CI/CD, el workflow operativo diario, semanal y mensual, y la estrategia de despliegue del IDOS.

2. Estrategia de CI/CD

2.1 Integración Continua (CI)
Todo commit a `main` ejecuta automáticamente:
- Linting (ruff)
- Tests unitarios (pytest, ~360 tests)
- Verificación de tipos (mypy, opt-in progresivo en módulos core)
- Validación de schemas YAML de `idos-config/`

2.2 Despliegue (CD)
El sistema se ejecuta localmente en el equipo del usuario. No hay despliegue a servidores remotos. Las actualizaciones se distribuyen via `git pull` desde el repositorio `idos`.

3. Workflows Operativos

3.1 Workflow Diario
8:00 - Market Open — Health Check: Verifica conectividad a fuentes de datos y brokers.
8:15 - Data Ingestion: Workers de datos ingieren noticias, precios, y eventos overnight.
8:30 - Market Observatory: Workers de Research analizan el mercado y generan alertas.
9:00 - Alert Review: El usuario revisa las alertas del Notification Center y toma decisiones.
15:30 - Market Close — Portfolio Update: Workers actualizan cartera y generan reporte diario.
16:00 - Daily Journaling: Workers registran eventos del día en `idos-journal/`.

3.2 Workflow Semanal
Lunes 12:00 — Weekly Strategy Review: Workers presentan análisis semanal.
Viernes 16:00 — Weekly Post-Mortem: Workers generan post-mortem de la semana.

3.3 Workflow Mensual
Día 1 — Monthly Portfolio Rebalance: Workers ejecutan rebalanceo mensual.
Día 1 — Monthly Report: Workers generan reporte mensual de rendimiento.
Día 5 — Conviction Review: Workers revisan y actualizan niveles de convicción.

3.4 Workflow Ad-Hoc
- Event-Driven: Eventos de mercado (earnings, macro data, breaking news).
- Board Decision: El usuario convoca al Board Worker para una decisión específica.
- Manual: El usuario ejecuta Workers a demanda.

4. Roles y Responsabilidades

4.1 Workers Programados
Se ejecutan en intervalos definidos en `idos-config/schedules/`:
- `health_check_worker.py`: Verifica APIs y conectividad.
- `market_observatory_worker.py`: Análisis diario del mercado.
- `data_ingestion_worker.py`: Carga de datos externos.
- `portfolio_worker.py`: Gestión de cartera.
- `journal_worker.py`: Registro de eventos en diario.
- `postmortem_worker.py`: Análisis post-mortem.

4.2 Workers Event-Driven
Se ejecutan en respuesta a eventos del bus:
- `research_worker.py`: Análisis fundamental/técnico de un ticker.
- `board_worker.py`: Síntesis de decisiones de inversión.
- `scout_worker.py`: Identificación de oportunidades de mercado.

4.3 Workers de Infraestructura
- `git_queue_worker.py`: Serializa escrituras a Git (CommitRequest).
- `notification_worker.py`: Gestiona alertas al usuario.
- `checkpoint_manager_worker.py`: Checkpointing y recovery.

5. Estrategia de Testing

5.1 Tests Unitarios
Cubren Workers, módulos core, SDK, y utilidades. Se ejecutan con pytest. Ubicación: `idos-core/tests/`.

5.2 Tests de Integración
Cubren flujos cross-module y Event Bus. Ubicación: `idos-core/tests/test_integration/`.

6. SDK Packaging
El paquete `idos-core/` se instala en modo editable (`pip install -e .`). El SDK se importa como `idos.sdk`. Dependencias especificadas en `pyproject.toml`.
