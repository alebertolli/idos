1. Objetivo
Este documento define la arquitectura lógica y física general del Investment Decision Operating System (IDOS). Su propósito es describir la organización de los componentes del sistema, sus responsabilidades y las reglas de integración que garantizan su escalabilidad y auditoría.

2. Principios Arquitectónicos
Toda decisión de diseño técnico e implementación de software en el IDOS debe respetar los siguientes principios:

2.1 Simplicidad y Fricción Mínima: Se prioriza el uso de herramientas e infraestructura simples y fiables (e.g., archivos de texto Markdown/YAML, SQLite, Python) antes de introducir sistemas complejos.
2.2 Bajo Acoplamiento: Los módulos del sistema nunca se comunican mediante llamadas directas. Toda interacción ocurre de manera asíncrona mediante la publicación de eventos en un bus central (`Event Bus`) o a través de interfaces estandarizadas del SDK.
2.3 Git como Fuente de Verdad Inmutable (Dual-Repo): Todo el conocimiento generado por el sistema se versiona en Git, pero se separa físicamente en dos repositorios según su naturaleza: `idos-knowledge` (hechos objetivos) e `idos-journal` (memoria de decisión subjetiva). La base de datos se puede borrar y reconstruir por completo a partir de ambos repositorios.
2.4 Independencia de Proveedores de IA (AI Agnostic): Las capacidades analíticas no dependen de un LLM o proveedor específico.
2.5 Intervención Humana Controlada (Human in the Loop): El software evalúa, filtra, propone y alerta; el humano confirma y autoriza las transacciones.
2.6 Estado Explícito y Trazable (State Machine): El ciclo de vida de toda `Opportunity` se modela como una máquina de estados lineal persistida en SQLite.
2.7 Serialización Centralizada de Escrituras (Git Commit Queue): Ningún Worker escribe directamente a los repositorios. Publica un evento `CommitRequest` al Event Bus. El Git Commit Manager es el único proceso autorizado para realizar `git push`, garantizando cero conflictos de concurrencia en ambos repositorios.
2.8 Cadena de Evidencia Completa (Provenance): Toda conclusión analítica debe estar vinculada a su cadena de evidencia original.

4. Componentes de la Arquitectura Física
El sistema físico se apoya en siete componentes fundamentales:

4.1 La Capa de Cuatro Repositorios (Split-Repo Setup)
El proyecto se divide físicamente en cuatro repositorios Git independientes:
- `idos-core`: Código, SDK, Workers, pruebas y workflows.
- `idos-config`: Prompts, reglas operativas, scoring y perfiles de riesgo.
- `idos-knowledge`: Conocimiento objetivo, verificable y reutilizable. Contiene fichas de empresas, datos financieros, transcripciones, wikis, sectores, eventos, riesgos y catalizadores. Debe poder compartirse o auditarse de forma independiente.
- `idos-journal`: Conocimiento personal y subjetivo. Contiene expedientes de inversión (Case Files), ventanas de oportunidad, decisiones del Board, post mortems, reflexiones estratégicas, notas de lectura y cambios de convicción. Representa la memoria de decisión del inversor y evoluciona en ciclos distintos al conocimiento objetivo.

4.2 IDOS SDK
Biblioteca común en Python utilizada obligatoriamente por todos los procesos.

4.3 Capabilities & Workers
Unidades lógicas de ejecución (Scheduled / Event-Driven, Data / AI).

4.4 Event Bus
Mecanismo central de mensajería asíncrona.

4.5 Knowledge Layer
Persistencia híbrida que combina:
- `idos-knowledge`: Conocimiento factual y verificable.
- `idos-journal`: Registro del proceso de toma de decisiones.
- SQLite: Índice rápido, máquina de estados, cola de commits y telemetría.

4.6 Provenance Engine
Garantiza la trazabilidad completa de cada conclusión analítica.

4.7 Notification Center
Centraliza las alertas al usuario y agrupa acciones críticas en la Decision Inbox.

5. Flujo de Datos General (Event-Driven Pipeline)
[Mundo Real] → [Event Bus] → [Worker] → [Knowledge Layer (KB + Journal)] → [Decision Orchestrator] → [Decision Board] → [Notification Center]

6. Persistencia y Almacenamiento
Nivel 1 - Git (Markdown / YAML): Fuente de verdad analítica dividida en `idos-knowledge` (tesis, datos, hechos) e `idos-journal` (expedientes, decisiones, aprendizajes).
Nivel 2 - SQLite: Índices, histórico, cola de eventos y telemetría.
Nivel 3 - Google Sheets: Dashboard financiero.
Nivel 4 - Almacenamiento Vectorial (Fase 3): Embeddings para RAG.
