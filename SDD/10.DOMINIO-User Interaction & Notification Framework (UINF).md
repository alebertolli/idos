# Investment Decision Operating System (IDOS)
## Software Design Document (SDD)
## Documento 10: User Interaction & Notification Framework (UINF)

Versión: 1.0  
Estado: Aprobado  

---

## 1. Filosofía de Interacción: Reducción del Ruido

El **UINF** se basa en un principio operativo estricto: **El IDOS no requiere que el usuario abra o consulte la aplicación diariamente**. 

El sistema debe comportarse como un analista o asesor senior de inversiones: no informa de cada cambio de datos menor ni de fluctuaciones cotidianas del mercado. Su objetivo es filtrar el ruido del día a día y amplificar únicamente los eventos y análisis que requieren una toma de decisión estratégica o una acción inmediata por parte del usuario.

---

## 2. Canales de Comunicación

El sistema distribuye la información a través de tres canales principales según la prioridad del evento:

| Evento de Negocio | Email (Resumen) | Telegram (Alerta) | Dashboard (Estado) |
| :--- | :--- | :--- | :--- |
| **Nueva oportunidad en Watchlist** | ✓ | No | ✓ |
| **Nueva oportunidad aprobada por Board** | ✓ | ✓ | ✓ |
| **Entrada en zona de compra** | ✓ | ✓ (Alta Prioridad) | ✓ |
| **Transacción de compra/venta ejecutada** | ✓ | ✓ | ✓ |
| **Rebalanceo de cartera propuesto** | ✓ | ✓ | ✓ |
| **Cambio material en la Conviction** | ✓ | ✓ | ✓ |
| **Tesis de inversión invalidada** | ✓ | ✓ (Alta Prioridad) | ✓ |
| **Alerta o stop de riesgo activado** | ✓ | ✓ (Alta Prioridad) | ✓ |
| **Resumen y Digest Semanal** | ✓ | No | ✓ |
| **Post Mortem finalizado** | ✓ | No | ✓ |

## 3. Niveles de Notificación

### 3.1 Nivel 1: Información (Baja Prioridad)
* **Descripción**: Eventos de mantenimiento y actualización en segundo plano. No requieren de ninguna acción o lectura urgente por parte del usuario.
* **Ejemplos**: Actualización de los datos trimestrales de una compañía en la `Knowledge Base`, recálculo automático de un indicador técnico o recalibración nocturna del backtesting.
* **Canal**: Exclusivamente registrados en la sección de logs del **Dashboard**.

### 3.2 Nivel 2: Atención (Mediana Prioridad)
* **Descripción**: Eventos que representan variaciones moderadas en la calidad del portfolio o cambios en las tesis de inversión. Se recomienda su lectura y análisis a corto plazo.
* **Ejemplos**: Incorporación de una nueva oportunidad al Watchlist, degradación del score de valoración de un activo o detección de un nuevo catalizador secundario.
* **Canal**: Envío consolidado por **Email** o a través del digest diario.

### 3.3 Nivel 3: Acción (Alta Prioridad)
* **Descripción**: Eventos que requieren una toma de decisión estratégica urgente o una confirmación de ejecución física en la cartera.
* **Ejemplos**: Oportunidad aprobada que entra en zona de margen de seguridad (zona de compra), falsación confirmada de hipótesis clave (*Thesis Broken*), activación del stop de riesgo o propuesta de reemplazo de un activo.
* **Canal**: Notificación instantánea vía **Telegram** (con prioridad y sonido) y **Email**.

## 4. El Concepto de Digest Inteligente

El IDOS prohíbe el envío individual y fragmentado de alertas cotidianas. En su lugar, el sistema implementa un **Digest Inteligente** consolidado:

* **Antes (IOS)**: Se enviaban múltiples notificaciones consecutivas como "Scout semanal finalizado", "Se encontraron 3 empresas", "ASML agregada a Watchlist", "Nike descartada", "TSMC subió de convicción", etc.
* **Ahora (IDOS)**: El usuario recibe un único mensaje consolidado al finalizar la semana con una estructura de lectura rápida (5 minutos):

```
📅 IDOS - RESUMEN SEMANAL
--------------------------------------------------
Scout ejecutado de forma automática sobre 1,248 empresas del universo.

[Nuevas Oportunidades]
- ASML ──► Ingresa al Watchlist (Score consolidado: 87)
- Nike ──► Descartada (Calidad del precio insuficiente)

[Cambios en Tesis Activas]
- MercadoLibre ──► Aprobada formalmente por el Decision Board.
- TSMC         ──► Convicción general se eleva de 81 a 89 (Margen de seguridad óptimo).
- Alphabet     ──► Nuevo catalizador IA incorporado a la base de conocimiento.

[Próximas Acciones Recomendadas]
1. Revisar orden de compra de MercadoLibre (en zona de margen de seguridad).
2. Autorizar el inicio de Due Diligence Profunda para ASML.
--------------------------------------------------
```

## 5. El Dashboard del IDOS

El Dashboard central de la interfaz de usuario se mantiene minimalista y funcional, estructurado únicamente en torno a **cinco widgets principales**:
1. **Portfolio Widget**: Muestra la evolución patrimonial neta, rentabilidad de la cartera, asignación de efectivo y nivel de drawdown actual.
2. **Watchlist Widget**: Las 10 oportunidades mejor valoradas bajo seguimiento.
3. **Buy List Widget**: Oportunidades autorizadas listas para comprar que se encuentran cerca de su zona de precio objetivo.
4. **Alerts Widget**: Notificaciones activas de riesgo o tesis debilitadas que requieren atención.
5. **Calendar Widget**: Fechas estimadas de próximos resultados trimestrales (10-Q/10-K), juntas de accionistas y revisiones automáticas planificadas.

**UI estática (GitHub Pages, sin servidor):** Adicionalmente, el sistema ofrece una
interfaz web **estática** publicable en GitHub Pages (`idos site-build`). Este sitio
organiza la información de gestión en vistas: Dashboard (acciones sugeridas + funnel +
alertas), Oportunidades (activas/cerradas con scores y stale), Buy List (zonas de
compra y Wyckoff), Portfolio (P/L por activo y total), Watchlist de screening, Wiki
por compañía y Learning (post-mortems). Se regenera automáticamente en el pipeline
CICD y se publica en Pages sin requerir servidor de aplicaciones.

## 6. Proactividad del Sistema

El IDOS actúa como un copiloto de inversión proactivo: inicia conversaciones y propone análisis estructurados en lugar de esperar de forma pasiva a que el usuario formule consultas.
* *Ejemplo de interacción*: "Hola. He detectado que ASML cumple con los filtros cuantitativos y su expectativa de retorno es superior a la peor posición actual de tu cartera. ¿Quieres que inicie la Due Diligence profunda y prepare el árbol de hipótesis?"
* *Ejemplo de interacción*: "Tras analizar los resultados de MercadoLibre publicados hoy, la probabilidad de éxito de la tesis (TSP) se ha elevado del 68% al 79%. No obstante, recomiendo mantener la espera de ejecución ya que la cotización actual sigue estando un 8% por encima de la zona de margen de seguridad óptima."

## 7. Bot Interactivo de Telegram

Además de las notificaciones unidireccionales, el sistema implementa un **TelegramBot** (`idos/workers/notifications/telegram_bot.py`) que permite al usuario consultar el estado del sistema mediante comandos interactivos desde Telegram.

### 7.1 Comandos del Bot

| Comando | Descripción | Implementación |
|---------|-------------|----------------|
| `/watchlist` | Watchlist actual con scores | Lee `watchlist.yml` del journal |
| `/dashboard` | Resumen del sistema | Agrega estado de workers + pipeline |
| `/scout TICKER1,TICKER2` | Screening bajo demanda | Ejecuta `ScoutWorker` en los tickers indicados |
| `/opp-list` | Oportunidades activas | Consulta SQLite de oportunidades |
| `/position-list` | Posiciones abiertas | Consulta SQLite de posiciones |
| `/event-log` | Eventos recientes | Últimos eventos del bus |
| `/help` | Lista de comandos disponibles | Respuesta estática |

### 7.2 Modos de Ejecución

- **Modo único** (`idos telegram-bot`): Procesa los mensajes pendientes de una sola pasada y termina. Ideal para workflows GHA.
- **Modo daemon** (`idos telegram-bot --daemon`): Bucle de polling continuo cada 30 segundos. Ideal para ejecución en segundo plano en Codespace.

### 7.3 Integración con Workflows

En los workflows de GHA, el bot se ejecuta como paso condicional con `if: failure()` para enviar alertas inmediatas al canal de Telegram cuando un worker falla, sin necesidad de consultar logs en GitHub.

```yaml
- name: Notify on failure
  if: failure()
  run: python -m idos.cli.main telegram-bot
```

### 7.4 Arquitectura

```
User (Telegram) ──getUpdates──► TelegramBot ──lee──► Watchlist / SQLite / Journal
                   ◄──sendMessage──                    │
                                                       ▼
                                                 Ejecuta Workers
                                                 (ScoutWorker, etc.)
```

El bot utiliza la misma API de Telegram que `TelegramNotifier` para enviar/rexibir mensajes, pero se diferencia en que el usuario inicia la conversación (pull) en lugar de recibir notificaciones push automáticas.

## 8. Bandeja de Decisiones (*Decision Inbox*)

Para evitar la dispersión de tareas y centralizar el flujo de gobierno humano del IDOS, el sistema implementa una **Bandeja de Decisiones (Decision Inbox)**.

Todas las propuestas que requieren intervención, validación o firma digital del usuario se listan en una única bandeja de entrada ordenada por prioridad operativa:

| Prioridad | Origen | Acción Requerida | Límite Estimado |
| :---: | :--- | :--- | :--- |
| 🔴 **Alta** | Portfolio / Entry | MercadoLibre en zona de compra. Autorizar transacción. | Hoy |
| 🔴 **Alta** | Risk / Exit | Hipótesis de Nike invalidada (Stop estructural). Confirmar venta. | Hoy |
| 🟡 **Media** | Research | Aprobar inicio de Deep DD para ASML. | Esta semana |
| 🟢 **Baja** | Learning | Revisar Post Mortem e informe de aprendizaje de PayPal. | Sin urgencia |

Con este diseño, el usuario puede gestionar el fondo completo de manera eficiente, centralizando las autorizaciones críticas y revisando el resto del conocimiento consolidado a su propio ritmo.
