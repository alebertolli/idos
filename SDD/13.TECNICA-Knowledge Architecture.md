Investment Decision Operating System (IDOS)
Software Design Document (SDD)
13: Knowledge Architecture - Arquitectura del Conocimiento
Versión: 1.2
Estado: Aprobado

1. Objetivo
Definir la arquitectura de almacenamiento de conocimiento en IDOS, incluyendo el depósito único de conocimiento (`idos-knowledge/`), el diario de decisiones (`idos-journal/`), el manejo de wikis atómicas, la configuración (`idos-config/`), y la integración con el repositorio Git.

2. Principios de la Arquitectura de Conocimiento

2.1 Atomicidad y Granularidad (Principio de Responsabilidad Única)
Cada pieza de información se almacena en su propio archivo o registro independiente. Wikis, Company Intelligence Briefs (CIBs), y eventos se organizan en directorios con un archivo por entidad.

2.2 Git como Fuente de Verdad Inmutable
Todo cambio en el conocimiento se versiona en Git. Un archivo una vez creado no se elimina; en caso de error o desactualización, se marca con un frontmatter `obsolete: true` y se crea uno nuevo.

2.3 Separación Lógica de Dominios (Knowledge vs Journal)
- `idos-knowledge/`: Contiene hechos objetivos, verificables, y reutilizables: Company Intelligence Briefs, fichas de empresas, datos financieros, wikis atómicas, definiciones de sectores e industrias, eventos económicos, riesgos, catalizadores y cualquier otra data verificable.
- `idos-journal/`: Contiene la memoria del proceso de decisión subjetivo: expedientes de inversión (Case Files), ventanas de oportunidad (Opportunities), decisiones del Board, post mortems, reflexiones estratégicas, notas de lectura, cambios de convicción, y cualquier contenido subjetivo o personal.

2.4 Enriquecimiento Progresivo
Todo worker puede enriquecer el conocimiento de manera asíncrona y concurrente, respetando el bloqueo por archivo a nivel de worker.
El sistema no requiere ni recomienda vectores ni embeddings en su núcleo, aunque puede utilizarlos opcionalmente.

3. Estructura de Directorios

3.1 `idos-knowledge/` — Conocimiento Factual (Objetivo, Verificable y Reutilizable)
idos-knowledge/
├── companies/          # Company Intelligence Briefs (CIBs), uno por empresa
│   └── <ticker>.md
├── wikis/              # Atomic wiki entries — piezas independientes de conocimiento
│   ├── technical/
│   ├── fundamental/
│   └── macro/
├── sectors/            # Definiciones de sectores e industrias
├── events/             # Eventos económicos y financieros
├── risks/              # Riesgos conocidos
├── catalysts/          # Catalizadores identificados
├── financials/         # Ratios, métricas y datos cuantitativos
└── templates/          # Plantillas para workers

3.2 `idos-journal/` — Memoria del Proceso de Decisión (Subjetivo y Personal)
idos-journal/
├── board/              # Decisiones, reuniones y acuerdos del Consejo
├── conviction/         # Cambios de convicción sobre activos
├── library/            # Notas de lectura, resúmenes, referencias
├── postmortems/        # Análisis post-trade, aciertos y errores
└── casefiles/          # Expedientes de inversión
    └── <ticker>/
        ├── thesis.md           # Tesis inicial
        ├── analysis/           # Análisis realizados
        ├── opportunities/      # Ventanas de oportunidad
        ├── decisions/          # Decisiones tomadas
        └── review.md           # Revisión post-mortem

3.3 `idos-config/` — Configuración operativa
idos-config/
├── prompts/            # Prompts del sistema (workers, evaluadores)
├── scoring/            # Reglas de scoring (fundamental, técnico, sentimiento)
├── risk/               # Perfiles de riesgo y stop-loss
├── indicators/         # Definición de indicadores
└── observatory/        # Metodología del Observatorio de Mercado

3.4 `idos-core/idos/data/` — Capa de acceso a datos en Python
La biblioteca `idos.data` expone:
- `knowledge.py`: Acceso a wikis atómicas y CIBs. Contiene el método `get_wiki_text()` que busca primero en wikis atómicas y falla a wikis monolíticas.
- `repository.py`: Abstracción sobre el sistema de archivos Git.
- `datasources.py`: Conectores a fuentes externas (Alpha Vantage, Yahoo Finance, scraping web).

4. Flujo de Escritura de Conocimiento
1. Worker analiza datos y genera contenido.
2. Worker escribe el archivo localmente bajo `idos-knowledge/` o `idos-journal/`.
3. Worker publica evento `CommitRequest` al Event Bus.
4. GitQueueWorker recoge el evento, ejecuta `git add`, `git commit`, `git push`.
5. Worker registra la cadena de proveniencia en la tabla `provenance_chain`.

5. AtomicWiki
El sistema soporta dos modos de almacenamiento de wikis:

5.1 Modo Atómico (Recomendado, activo por defecto):
Cada entrada de wiki se almacena en su propio archivo dentro de `idos-knowledge/wikis/` organizado por categorías (technical/, fundamental/, macro/). Cada archivo contiene frontmatter YAML con metadatos (ticker, categoría, fuentes, creador, timestamp) y el cuerpo en Markdown.

5.2 Modo Monolítico (Deprecado):
Una única wiki.md por ticker. El sistema soporta lectura de este formato para compatibilidad hacia atrás, pero toda escritura nueva se realiza en formato atómico.

6. Atomic Wiki Storage (Detalle de Implementación)
El método `get_wiki_text()` en `idos-core/idos/data/knowledge.py` implementa:

1. Buscar archivos en `idos-knowledge/wikis/<category>/<ticker>.md` para cada categoría.
2. Si se encuentran entradas atómicas, concatenarlas y retornarlas.
3. Si no se encuentran, buscar wiki monolítica en `idos-knowledge/wikis/<ticker>.md`.
4. Si no existe ninguna, retornar cadena vacía.

7. Provenance
Todo contenido generado por un Worker se vincula a sus fuentes mediante el `ProvenanceEngine` (`idos-core/idos/provenance/engine.py`). Cada registro de proveniencia almacena:
- `conclusion_id`: Identificador único de la conclusión generada.
- `evidence_id`: Identificador único de la evidencia original.
- `evidence_type`: Tipo de evidencia (company_yml, wiki, financial_data, market_data, event, external_source).
- `source`: Origen de la evidencia (ticker, URL, nombre de archivo).
- `timestamp`: Momento en que se registró.
- `metadata`: JSON con contexto adicional (modelo usado, confianza, parámetros).
