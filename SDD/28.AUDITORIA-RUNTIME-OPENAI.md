## Correcciones

1. Calendario earnings: reloj opcional inyectable sin modificar el valor por
   defecto de producción. Pruebas con fecha fija y borde de cinco días.
   Timestamps inválidos y entradas no diccionario no abortan eventos válidos;
   fechas YAML nativas se normalizan para la revisión de antigüedad.
2. CI: evaluar la captura del log dentro del shell antes del reporter.
3. `LLMWorker()` aceptaba configuración opcional pero hacía `None.get()`;
   usa la configuración normalizada. Su respuesta estructurada ya serializa
   el nombre de modelo cuando se inyecta `LLMService`, en lugar de un método.
4. `LLMService.model()` devuelve cadena vacía si falta el cliente por defecto,
   evitando `AttributeError`. Se registran los markers smoke/e2e existentes.
5. Un fallback de modelo vacío ya no introduce un modelo Gemini en OpenAI,
   Groq u OpenRouter. La variable explícita `IDOS_LLM_FALLBACK_MODEL` sigue
   disponible cuando no se proporciona el argumento; la configuración de
   servicio vacía desactiva ese fallback.
6. Build: el descubrimiento automático incluía `tests` y `build/lib` como
   paquetes. El segundo wheel creció hasta 655 archivos, incluidos 325 bajo
   `build/` y 129 bajo `tests/`. Se limita el finder a `idos`/`idos.*` y se
   agrega `scripts/check_wheel_contents.py` a CI. La verificación inspecciona
   el ZIP sin instalarlo ni extraerlo y rechaza contenido ajeno o entrypoints
   ausentes. Cuatro pruebas cubren esas condiciones.

universo operable, las reglas financieras, los approvals ni la frontera de
portfolio. OpenAI puede tener costo; estos límites no representan crédito
disponible y los presupuestos globales declarados no se certifican aquí.
Referencia de contrato: [OpenAI API — Create chat completion](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).

El modelo se eligió por compatibilidad con el adaptador existente y costo

sustituirse y validarse antes de esa fecha. Esta integración no certifica una

El 2026-11-18 se solicita explícitamente una prueba real antes de integrar y
seleccionar el modelo actual recomendado con consumo bajo. La selección vigente
se actualiza a **gpt-6-luna** a pedido del usuario, tras dos pruebas anteriores
con HTTP 401 usando gpt-6.2-sol. La información anterior de modelo corresponde
a la configuración histórica.
Fuentes oficiales consultadas:
- https://developers.openai.com/api/docs/models/gpt-6-luna (Luna es el modelo
  más eficiente para tareas acotadas y de alto volumen; ID `gpt-6-luna`).
- https://developers.openai.com/api/docs/guides/model-selection (Luna se
  recomienda para tareas frecuentes y acotadas).

Se configura razonamiento low, compatible con Luna en Chat Completions, porque
este flujo sintetiza evidencia suministrada
con contextos previamente acotados; es una elección de eficiencia que requiere
validación de calidad posterior, no una garantía sobre Research completo.
El adaptador aplica min(límite del worker,8192) tokens de finalización,
incluyendo razonamiento, conserva JSON y rechazo de truncamientos, y registra
razonamiento consumido. Modelos anteriores mantienen temperature. Sin cambios
a prompts financieros, reglas, universo, approvals ni portfolio. OpenAI permanece
último proveedor. Rollback: restaurar modelo/configuración y adaptador previos.

La prueba reusable scripts/smoke_openai.py utiliza el adaptador real, una llamada
sin reintentos, 30 s y máximo 512 tokens de finalización. Datos sintéticos:
revenue=100 y operating_profit=20, sin targets. Exige margen 20, abstención de
valoración por datos insuficientes y trade_authorized=false. Un resultado verde
sólo demuestra acceso al modelo y ese contrato mínimo. No valida tesis ni cuota
para cargas grandes. CI permite activar el job exclusivamente con dispatch
manual openai_smoke=true; los PRs ejecutan regresiones sin consumir la API.
Se persiste un JSON con modelo, uso, latencia y resultado, sin claves ni headers.
La evidencia final del run y del SHA se registra en el PR #359.
