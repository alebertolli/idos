## Estados del State Machine

Flujo de Producción (canon SDD-7 v2.1):

```
SCREENED → UNDER_RESEARCH → APPROVED | WATCHLIST → ENTRY_PENDING → ACCUMULATING → EXITED → POST_MORTEM → ARCHIVED
```

`SCREENED` es la entrada al ciclo (creado por el Scout con score ≥ threshold). `WATCHLIST` es estado terminal automático al que caen opps cuando el score baja del threshold. Una opp en `WATCHLIST` nunca se reprocesa automáticamente; solo se reactiva si el Monthly Universe detecta score ≥ threshold. `DISCOVERED` se reserva para creación manual vía CLI.

Estados de trazabilidad manual (no forman parte del flujo automático): `FULL_POSITION`, `MONITORING`, `REDUCING`.

## Registro de investigación fallida — 2026-10-17 (run #445)

En [DDD #445](https://github.com/alebertolli/idos/actions/runs/39047714155), sobre la rama de prueba y con un único candidato VIST, Research tardó 8m15s y terminó con `ddd_failed`: el proveedor de Gemini respondió `401 Unauthorized`, Groq devolvió 404 y OpenRouter agotó la salida a 4096 tokens con JSON incompleto. `cache/ddd_results.json` registró un error, pero el script devolvió éxito y permitió que assessment/monthly/digest continuaran sin trabajo. Esto se clasifica como falla funcional aunque Actions haya informado verde.

El job inyectó `GEMINI_API_KEY`; el 401 significa que el servicio no aceptó el valor/configuración, no que GitHub omitiera el secreto. El adaptador también estaba poniendo la clave en el query string de la URL, y el log público mostró parte de ella. Revocar y rotar la clave es requisito antes de otra llamada real. Gemini documenta el encabezado `x-goog-api-key` para autenticación REST. La referencia de error Gemini define 401 como clave ausente, inválida o expirada: revisar en AI Studio/Cloud que la nueva clave y el proyecto tengan acceso a Generative Language API.

Correcciones locales preparadas en la rama de prueba: usar `x-goog-api-key` en el encabezado; redactar credenciales de diagnósticos; al agotar 429 no invocar otro modelo del mismo proveedor; persistir los resultados y fallar el paso DDD si algún candidato da `ddd_failed`; condicionar commit/artifact para guardar evidencia incluso cuando Research falla. Las pruebas focalizadas locales pasaron (29), el YAML parsea y `git diff --check` está limpio. No se ha iniciado un workflow remoto tras estos cambios. Próximo gate: el gestor rota la clave; luego se ejecuta una sola prueba focalizada, se comprueba que el log no contenga secretos, que DDD produzca JSON/tésis válida o falle claramente, y que los pasos downstream se bloqueen al fallar.
