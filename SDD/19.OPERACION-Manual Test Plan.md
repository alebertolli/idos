# Plan de Testeo IDOS — Validación Manual

## Procesos del Sistema

---

### 1. Discovery → Oportunidades

**Trigger:** Workflow `monthly-universe-pipeline.yml` (cron: 1er día del mes 00:00)

| Paso | Ejecutar | Verificar |
|------|----------|-----------|
| 1.1 | Finviz Screener (5 screeners) | `cache/pipeline_results.json` → `finviz_count` (~1000-3000 tickers) |
| 1.2 | Operability Filter | `cache/pipeline_results.json` → `operable_count` (~200-600) |
| 1.3 | Data Fetch (stockanalysis.com) | `cache/pipeline_results.json` → `fetch_new` / `fetch_cached` |
| 1.4 | ScoutEngine Scoring | `cache/pipeline_results.json` → `scout_passed` / `scout_rejected` |
| 1.5 | Opportunity Creation (score ≥70) | `cache/pipeline_results.json` → `opportunities_created` |
| 1.6 | SQLite Insert | `idos.db` → query `SELECT * FROM opportunities WHERE status='DISCOVERED'` |
| 1.7 | Watchlist YAML | `idos-journal/portfolio/watchlist.yml` → nuevas entradas con score |
| 1.8 | Wiki Creation | `idos-knowledge/companies/{TICKER}/company.yml` creado |
| 1.9 | Notificación Telegram | Mensaje: "IDOS Monthly Universe Pipeline" con métricas |
| 1.10 | Git Commit | Commit "chore: monthly universe pipeline YYYY-MM-DD" |
| 1.11 | IDOS Dashboard (`idos dashboard`) | Active Opportunities refleja los nuevos DISCOVERED |
| 1.12 | IDOS Opt-List (`idos opp-list`) | Nuevas oportunidades visibles con status=DISCOVERED |

### 2. Decision (Research + Assessments + Board + Buy List)

**Trigger:** Workflow `ddd-pipeline.yml` (cron: 2do día del mes, o post-universe, o quarterly-results, o manual)

#### 2.1 Research (DDD + AOIF + Hypothesis)

| Paso | Ejecutar | Verificar |
|------|----------|-----------|
| 2.1.1 | ResearchWorker ejecuta DDD | `idos-journal/companies/{TICKER}/case_file/opportunities/{OPP}/ddd_report.yml` existe con contenido |
| 2.1.2 | AOIF 8-step protocol | `ddd_report.yml` → `error_mercado`, `hipotesis_contraria`, `catalizador_cambio` |
| 2.1.3 | Hypothesis Generation | `ddd_report.yml` → `score_general`, `clasificacion_oportunidad` |
| 2.1.4 | Wiki Generation | `idos-knowledge/companies/{TICKER}/wiki/` → secciones atómicas creadas |
| 2.1.5 | SQLite Status Update | `SELECT * FROM opportunities WHERE ticker='{TICKER}'` → status='UNDER_RESEARCH' |

#### 2.2 Assessment Engines (STEP 3-7)

| Paso | Ejecutar | Verificar |
|------|----------|-----------|
| 2.2.1 | BusinessAssessmentEngine | assessment file → score + findings |
| 2.2.2 | ValuationAssessmentEngine | assessment file → score + re-rating probability |
| 2.2.3 | RecoveryAssessmentEngine | assessment file → score + margin of safety |
| 2.2.4 | RiskAssessmentEngine | assessment file → score + risk factors |
| 2.2.5 | PortfolioAssessmentEngine | assessment file → score + portfolio fit |
| 2.2.6 | ConvictionCalculator | `decision_proposal.yml` → `conviction_score` (weighted avg 0-100) |

#### 2.3 Rules Engine

| Paso | Ejecutar | Verificar |
|------|----------|-----------|
| 2.3.1 | Rules RULE-001 a RULE-008 | `decision_proposal.yml` → `rules_passed` / `rules_failed` |

#### 2.4 Board Decision

| Paso | Ejecutar | Verificar |
|------|----------|-----------|
| 2.4.1 | DecisionBoard auto-review | `board_resolution.yml` → `approved` (bool) + `decision_type` (AUTO_APPROVED / PENDING_REVIEW / AUTO_BLOCKED) |
| 2.4.2 | SQLite Status Update | `SELECT * FROM opportunities` → status='APPROVED' (si passed) o 'WATCHLIST' (si failed) |

#### 2.5 Entry Evaluation

| Paso | Ejecutar | Verificar |
|------|----------|-----------|
| 2.5.1 | EntryEvaluation (si APPROVED) | `entry_evaluation.yml` → indicador compuesto (fase, score), price zone, target price |
| 2.5.2 | Buy List Update | `idos-journal/portfolio/buylist.yml` → entrada agregada (si APPROVED) |

#### 2.6 Notificaciones

| Paso | Ejecutar | Verificar |
|------|----------|-----------|
| 2.6.1 | Telegram | Mensaje: "IDOS DDD Pipeline" con resumen de resultados |
| 2.6.2 | Email | Email "IDOS DDD Pipeline Report" con detalle de cada oportunidad |

#### 2.7 Artefactos

| Paso | Ejecutar | Verificar |
|------|----------|-----------|
| 2.7.1 | `cache/ddd_results.json` | Contiene processed, assessments, errors |
| 2.7.2 | `cache/weekly_digest.md` | Digest generado del DDD Pipeline |
| 2.7.3 | Git Commit | "chore: ddd research YYYY-MM-DD" |

### 3. Board Review (Post-Decision)

**Trigger:** Workflow `board-review.yml` (cron: 4to día del mes 06:00)

| Paso | Ejecutar | Verificar |
|------|----------|-----------|
| 3.1 | Scan decision_proposal.yml en todas las oportunidades | `cache/board_proposals.json` → proposals list |
| 3.2 | Clasificar: PENDING_REVIEW / AUTO_APPROVED / AUTO_BLOCKED / DECIDED | `board_proposals.json` → `status` por cada propuesta |
| 3.3 | Generar Board Review Report | `cache/board_review.md` creado |
| 3.4 | Telegram | Mensaje "IDOS Board Review" con pending/approved/blocked count |
| 3.5 | Email | "IDOS Board Review" con detalle de propuestas |
| 3.6 | Ver artefacto | `cache/board_proposals.json` + `cache/board_review.md` |
| 3.7 | **Manual Action Required:** Revisar PENDING_REVIEW proposals y decidir | Decidir APPROVE o REJECT vía `idos opp-approve` o `idos opp-reject` |

### 4. Entry Monitor (Buy List → Ejecución)

**Trigger:** Workflow `daily-refresh.yml` (cron: L-V 08:00) + scheduler `entry_monitor` (09:30)

| Paso | Ejecutar | Verificar |
|------|----------|-----------|
| 4.1 | Cargar Buy List | `idos-journal/portfolio/buylist.yml` → entries con `monitoring: true` |
| 4.2 | EntryMonitorWorker por ticker | Log: "Monitoreando N oportunidades en Buy List" |
| 4.3 | Indicador compuesto de entrada | `entry_evaluation.yml` → `wyckoff_phase`, `wyckoff_score` (demanda/absorción/oferta/distribución) |
| 4.4 | Price in Buy Zone | `entry_evaluation.yml` → `price_in_zone`, `margin_of_safety_pct`, `target_price` |
| 4.5 | Thesis Check | `entry_evaluation.yml` → `thesis_active` |
| 4.6 | Portfolio Fit | `entry_evaluation.yml` → `portfolio_fit` |
| 4.7 | Entry Conditions Met | `entry_evaluation.yml` → `all_conditions_met` |
| 4.8 | **Si conditions met:** Transition a ACCUMULATING | `SELECT * FROM opportunities` → status='ACCUMULATING' |
| 4.9 | **Si conditions met:** Position creation | `idos-journal/portfolio/positions/{TICKER}.yml` creado |
| 4.10 | Ver vía CLI: `idos entry-evaluate {TICKER}` | Tabla con condiciones entry (price_in_zone, wyckoff, etc.) |
| 4.11 | Ver vía CLI: `idos position-list` | Posición visible con shares, avg price, weight |
| 4.12 | Buy List Refresh (diario) | `idos-journal/portfolio/buylist.yml` → `target_price` y `buy_zone_top` actualizados (`buy_zone_top = intrinsic/(1+MoS/100)`) |
| 4.13 | Snapshot de entrada | `entry_snapshot.yml` generado al comprar: thesis, assessments, técnicos (wyckoff), catalizadores, riesgos, dominios y fundamentales |
| 4.13 | Error de datos | `cache/data_errors.json` registra el error (dedup por día+ticker); sin `target_price` → severidad alta, no compra |

### 5. Risk Monitor (Diario)

**Trigger:** Workflow `daily-refresh.yml` step "Risk Monitor" + scheduler `risk_monitor` (08:00)

| Paso | Ejecutar | Verificar |
|------|----------|-----------|
| 5.1 | Cargar positions activas | `idos-journal/portfolio/positions/` → todos los YML |
| 5.2 | Check Drawdown >15% | Alerta HIGH si drawdown supera umbral |
| 5.3 | Check Stop Loss | Alerta CRITICAL si stop loss triggered |
| 5.4 | Check Concentration >3% | Alerta MEDIUM si posición >3% del portfolio |
| 5.5 | Generar alerts | Output: `positions_checked`, lista de `alerts` con severity |
| 5.6 | Notificación (si alerts) | Telegram con alertas de riesgo |
| 5.7 | Ver vía CLI: `idos position-list` | Posiciones con pesos actualizados |

### 8. Post Mortem (Al Salir)

**Trigger:** Workflow `daily-refresh.yml` step + CLI `idos position-exit`

| Paso | Ejecutar | Verificar |
|------|----------|-----------|
| 8.1 | Detect EXITED opportunities | SQLite → `SELECT * FROM opportunities WHERE status='EXITED'` |
| 8.2 | Check post-mortem no existe | Verificar que `post_mortem/` dir no tenga YML previo |
| 8.3 | Check snapshot de entrada existe | `entry_snapshot.yml` presente en el caso; verificar thesis, assessments, wyckoff de entrada, catalizadores y riesgos |
| 8.4 | PostMortemWorker ejecuta | Output: `exit_analysis`, `thesis_was_correct`, `lessons_learned`, `biases_detected`, `would_invest_again`; prompt evalúa la tesis y el análisis del momento de entrada, no el del cierre |
| 8.5 | Generar post_mortem YAML | `idos-journal/companies/{TICKER}/case_file/opportunities/{OPP}/post_mortem/{pm_id}.yml` |
| 8.6 | FeedbackCollector registra | Learning loop actualizado |
| 8.7 | HitRateTracker actualiza | Hit rate recalculado |
| 8.8 | Transition EXITED → POST_MORTEM → ARCHIVED | SQLite → status='ARCHIVED' |
| 8.9 | Ver vía CLI: `idos opp-show {TICKER}` | Post-mortem visible en detalle |

## Estados del State Machine

Flujo de Producción (canon SDD-7):

```
DISCOVERED → UNDER_RESEARCH → APPROVED | WATCHLIST → ENTRY_PENDING → ACCUMULATING → EXITED → POST_MORTEM → ARCHIVED
```

Estados de trazabilidad manual (no forman parte del flujo automático): `SCREENED`,
`FULL_POSITION`, `MONITORING`, `REDUCING`.
